# Fare Desk workflow

- The route field accepts one three-letter airport pair per line. The server validates and deduplicates routes. Airport availability is decided by IndiGo's live response, not by the form.
- Travel date choices are T+1, T+5, T+9, T+15, T+30, and T+45 from the India calendar day at batch start.
- A run covers the full route/date Cartesian product. The page chooses worker count automatically (one for a single search, up to two for a batch). At most 36 searches are allowed, and starts are separated by at least 20 seconds. The user chooses only routes, dates, and browser mode.
- The stage bar reflects only collector `search_stage` records. During collection the page shows the real captured/expected journey count. A fare appears only after the saved run passes `verifyRun` and the fare is present in the saved result.
- The normal mode checks every exact-route journey in the airline response against its displayed page row, flight numbers, and starting price. It records base fare and taxes from that matching response. A missing or mismatched journey makes the search incomplete; it must not claim full coverage. The compact results table shows every captured flight, its times, stops, starting fare, and saved evidence.
- Visible Chrome and headless Chrome are explicit choices. Headless Chrome launches with `--headless=new` and a version-matched normal Chrome user-agent string. A direct headless DEL–BOM run and a page-run headless LKO–PAT run passed fare verification. Both choices use separate persistent profiles and the same source-verification rule; the saved manifest states the actual browser mode.
- A denied or challenged search stops queued work and interrupts other active agents. Each stopped task records a cause. A failed or empty search never becomes a sold-out claim.
- A failed, partial, interrupted, or skipped card with a future date offers a one-search action. The server reads the saved route, exact travel date, and browser mode from that card, starts a new one-worker run, and links it to the original run; it never rewrites old evidence or recalculates the date from T+. A skipped card says “Run this search” because it was never sent. An active run blocks another launch. Explicit access denial, CAPTCHA, rate limiting, or session denial does not offer a retry from that batch.
- A page reload restores the latest run. If the server was stopped during a run, uncompleted tasks are labeled interrupted. The Stop button interrupts the active batch.
- Progress updates use a same-origin event stream. If it disconnects, the page says it is reconnecting. Failure causes and evidence links remain available in the saved run.
